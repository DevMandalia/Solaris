Solaris Pod — WhatsApp intelligence

Shipped in agent

Daily standup always minted a new in-progress card. Evening “done” replies were treated as late standup. Group chat with the bot felt like a script, not a teammate.

Root cause. The capture plugin intercepts directed WhatsApp messages with regex and leftover ritual-session.json before the Hermes LLM ever sees them. It was designed to jot-and-ack, not to understand which ticket you picked or which prompt you replied to.

01

The three issues

Three separate failures, one architecture. The board is the work record; WhatsApp is transport.

1 · Duplicate tickets
You pick a ticket already in backlog or doing-this-week. The bot creates ONE · Name · focus and parks it in in-progress. The real card never moves. 13 Aug: “setting up TastyTrade backtesting today” minted a Strategy wrapper while TastyTrade / backtest cards sat in Trading backlog.
2 · Evening wrap ignored
You replied “done” to the 19:30 wrap. The bot answered as if that were a late reply to the 09:15 standup. Wrap copy is “ONE thing wrap”; the standup detector matched any quoted text containing “one thing”.
3 · Mechanical voice
Directed group messages hit a command table, then ritual regex, then a canned ack. The LLM only sees leftover chat that survived the intercept. SOUL even forbade thinking on check-ins.

02

Why it happens

Every @Solaris / reply-to-bot message goes through solaris-capture → handle_message. The first handler that returns a response wins. The Hermes agent never runs.

OrderHandlerWhat it matchedFailure mode
1 Champion commands help, standup, hygiene, 1:, quiet Fine — keep deterministic
2 record_ritual_reply Quoted text matching /one thing/ or any short line in the standup window Wrap quotes matched. Expired standup session still in ritual-session.json. “done” stolen.
3 record_one_thing_wrap_reply Bare done / still while wrap_open Ran too late. Did not strip [Replying to: …].
4 create_or_update_one_thing_task Always wrote one-YYYY-MM-DD-owner.md Never searched backlog / doing this week / in progress
BUGQuoted-context regex

Standup context was (daily standup|standup|one thing|highest-priority|60 min|20 min). The evening prompt is titled “ONE thing wrap”, so a WhatsApp reply-to that bubble looked like a standup reply. After 10:15 PT the standup session is expired, so the handler returned the closed-window speech instead of the wrap handler.

Confirmed copy from cron 13 Aug 19:30: “ONE thing wrap / Did you finish today's focus? / Reply: done or still”.

03

Target flow

Keep slash-like commands deterministic. The morning standup is a numbered pick list from the board. Everything else aimed at Solaris gets quoted-prompt detection, ticket matching, and a real conversation when it is not a ritual.

IfThen
Reply to wrap, or wrap window + done/stillMark the linked ticket done (or leave in progress). Never mention standup.
Reply to standup with 1–N, or a title from the morning listMove that offered ticket to in progress now. Ack names the real title.
Free text unlike the listSearch the whole open board (offered list first). Create only after a miss, or on new:.
Two people pick the same cardWarn. Do not dual-own. Ask if they still join or pick another number.
Reply new: … or “not on the board”Create a real ticket with that title.
Question, conversation, @Solaris about the boardDo not intercept. Hermes agent answers with vault + board tools.
help / standup / hygiene / 1: / quietUnchanged deterministic briefs.

Morning prompt: this week, then already in progress

The 09:15 message lists all of doing this week, then already in progress now (real tickets; daily ONE · wrappers are skipped). Sort inside each section by kanban_order as it stands. Backlog is not padded onto the list. Free text still searches the whole open board before minting.

Same or substantially the same work already on the board. Lane becomes in progress now. Today’s ONE-thing pointer stores that path. No wrapper card.

Genuinely new work, or an explicit new: line. Title is the focus, not “ONE · Name · …”. Park in in progress now. Wrap “done” closes this card.

LLM is the matcher, not a coach on every ping. Rituals stay short. The numbered list makes “which ticket?” obvious for both humans and the bot.

04

Ship plan

Implementation is in Solaris-agent (the Pod), not the Solaris CLI repo. Hermes already symlinks scripts and the capture plugin.

SliceChangeDone whenDone
P0 Quote-kind routing Wrap vs standup never share a regex. Unwrap [Replying to:]. Wrap handler runs first. Opening wrap overwrites ritual-session kind.
P1 Board match on standup List open tickets → LLM (fallback Jaccard) → move or create. Skip old ONE · wrappers. Ack says moved vs created.
P1b This-week + in-progress pick list Standup lists all doing this week, then already in progress (no ONE wrappers, no backlog padding). Reply 1–N moves that card. Free text searches the whole board. new: … creates. Collision warns, no dual-own.
P2 Intent pass-through Questions and non-ritual @Solaris go to Hermes. Questions during standup window are not stolen as focus lines.
P2 Voice / SOUL SOUL + skill: match the board first; converse when directed; still no coaching stack on a one-line check-in.
Test Regression pack Reply-to wrap “done” after expired standup; match existing backlog title; create when no match; this-week + in-progress list; collision warn; “?” not treated as focus.
